# Rough plans and layout interviews

The Layout tab offers three wholly synthetic starting plans or a room-name/adjacency interview. The initial rectangles and 14ft interview defaults are estimates. `A -> B` places an adjacent pair toward the east initially; the editor lets the user correct the direction, positions and familiar room names. Unrecognized adjacency prose is retained as interview evidence, not treated as solved geometry. North is at the top; positive x is east, positive y is south.

Select a wall segment directly in the drawing, or choose room/segment in the form. The length box accepts `8.5ft`, `72 inches`, `8' 3.25"`, and meters; a bare number is feet. Raw input is retained alongside canonical feet. Applying a segment changes that room's rectangular extent. Other rooms stay in place; overlap warnings prompt local correction. Opposite measured segments and irregular shapes need agent refinement. No doors, stairs, windows or physical accuracy are inferred.

`POST /api/home/layout` saves an own-account immutable draft in `/shared/home-twin/<id>/contributions/layout-drafts/` (legacy home uses its own root). Each save has a stable UUID; retries cannot change that ID's content. Server stamps actual account and time. The draft stays `needs-layout-review` and a geometry contribution enters the maintainer's review queue. Existing home model and all earlier drafts remain intact. A viewer cannot write.

`GET /api/home/layout` returns the caller's own saved drafts and accepted plan. Contributors explicitly share their home contribution folder with the maintainer; the nested layout-draft folder travels with it. The agent reads the registered member's folder with authenticated attribution, compares accepted revision and draft evidence, then publishes an explicitly reviewed accepted plan as part of a versioned snapshot. The current UI does not auto-apply major layout changes or solve an irregular multi-floor scan. Different floor names/drafts are retained; further captures can replace estimates gradually.
